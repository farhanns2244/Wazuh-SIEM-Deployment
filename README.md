## What Is SIEM?

Security Information and Event Management (SIEM) is a technology used to
collect, centralize, and analyze security logs and events from different
sources.

Common SIEM functions include: - Collecting logs from endpoints,
servers, firewalls, network devices, applications, and cloud services. -
Parsing and normalizing logs into structured fields. - Storing and
indexing events for searching. - Correlating related events from
different systems. - Generating alerts for suspicious activity. -
Supporting incident investigation and reporting.

## Concepts Studied

### 1. SIEM, SOAR, EDR, and XDR

  -----------------------------------------------------------------------
  Technology                          Main purpose
  ----------------------------------- -----------------------------------
  SIEM                                Collects, centralizes, correlates,
                                      and analyzes logs.

  SOAR                                Integrates security tools and
                                      automates incident-response
                                      workflows using playbooks.

  EDR                                 Monitors endpoint activity and
                                      supports endpoint threat detection
                                      and response.

  XDR                                 Correlates telemetry across
                                      multiple security layers, such as
                                      endpoints, networks, email,
                                      identity, and cloud services.
  -----------------------------------------------------------------------

These technologies support different parts of security operations. SIEM
focuses on log visibility and analysis, SOAR on response automation, EDR
on endpoint visibility, and XDR on detection across multiple layers.

### 2. Log Integration into SIEM

Logs can be generated by firewalls, endpoints, servers, network devices,
security products, and cloud services.

The study material describes three common integration methods:

**Syslog-based integration** - Devices send log messages using the
Syslog protocol. - Common ports include UDP 514, TCP 514, and TCP 6514
for Syslog over TLS. - It is commonly used with Linux systems and
network devices.

**Agent-based integration** - An agent is installed on an endpoint or
server. - The agent collects local logs and forwards them to the SIEM. -
This method can support reliable collection, filtering, and buffering.

**API-based integration** - The SIEM connects to an application's API. -
Authentication is performed using API credentials. - Logs are retrieved
at scheduled intervals or through supported near-real-time mechanisms.

Before analysis, raw logs may be parsed to extract useful fields and
normalized into a common format. The SIEM can then store and index
events for searching and correlation.

### 3. Threat Intelligence Feeds and Syslog Servers

Threat intelligence feeds provide information about known or emerging
threats, including: - Malicious IP addresses and domain names - Phishing
URLs - Malware file hashes - Command-and-control (C2) servers -
Indicators of Compromise (IOCs) - Vulnerabilities and exploit
information

The study document lists these example sources: - AlienVault OTX -
VirusTotal - AbuseIPDB - Cisco Talos Intelligence - IBM X-Force
Exchange - MISP - Recorded Future - OpenPhish - Spamhaus

A **syslog server** is a centralized server that collects, stores, and
manages log messages from devices and systems. Example sources include
firewalls, routers, switches, Linux servers, IDS/IPS, web servers, VPN
gateways, and applications.

Threat intelligence can provide context for investigating events found
in logs. For example, a SOC analyst may compare an IP address in a
security log with threat intelligence information to assess whether it
is associated with known malicious activity.

### 4. Data Loss Prevention (DLP)

Data Loss Prevention aims to protect sensitive information from
unauthorized disclosure, accidental exposure, or theft.

  -----------------------------------------------------------------------
  DLP type                            Main focus
  ----------------------------------- -----------------------------------
  Endpoint DLP (EDLP)                 Protects data on endpoint devices
                                      and monitors activities such as
                                      file access, USB usage, printing,
                                      and clipboard operations.

  Network DLP (NDLP)                  Inspects data in motion, including
                                      web uploads, FTP transfers, and
                                      other network communications.

  Email DLP                           Inspects outgoing email content,
                                      attachments, and recipients to
                                      reduce unauthorized disclosure
                                      through email.
  -----------------------------------------------------------------------

These DLP topics are part of the study material. This repository does
not claim that DLP controls were deployed as part of the Wazuh
configuration.
